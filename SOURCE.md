# Where Larder's source comes from

- **Base foundation.** Composed with Base's foundation and edition tools from `runeditrun/base` at `79f61faef682f9d6cdb64e843cfbd3cf02887982`, then moved to package mode: commands run from the exact `@runeditrun/rer` pin in `package.json`, with no vendored CLI.
- **Copied Base modules.** `src/base`, `src/modules/{ai,dependencies,mail,operator-auth,owner-claim}` and `src/modules/import-kit` (without its tests) are byte-exact copies of that Base revision, recorded file by file with SHA-256 in `base-copies.json`; `rer check` verifies the operator-auth copy. `src/base/hydration/README.md` is the one edited file: the package-mode conversion rewrote its command guidance. `src/modules/mail/src/core/validation.mjs` and `src/modules/mail/src/inbound/headers.mjs` also differ: their address and header regexes were replaced with linear parsing (CodeQL js/polynomial-redos), and `base-copies.json` records the edited hashes. `migrations/core/0014_import_kit.sql` is Base's import-kit D1 schema from `default-seed/migrations/core/0018_import_kit.sql` at the same revision.
- **Larder's own source.** `src/larder/`, `src/ui/`, `migrations/core/0013_larder.sql`, `tests/` and `fixtures/` are Larder's. The append-only ledger with versioned atomic commits, the Worker/D1 test harness and the browser runtime follow patterns from Pier (`just-every/run-pier`, MIT), re-implemented for Larder's BOM, production, lot, handoff and agent workflows.
- **Design.** The app screens were built from a 12ui order-workspace design picked from four candidates.
