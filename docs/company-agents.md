# Company agents

Larder exposes one company-agent door at `/mcp`. Discover it with `server/discover` or `/.well-known/oauth-protected-resource/mcp`. Both supported MCP versions, `2026-07-28` and `2025-11-25`, expose the same registry. March 2025 is refused. `/agents` shows company policy, Pause, approvals, reviews and audit. The account menu links to it.

The current declaration is the core planner subset: tools, signed policy, Pause, audit and idempotency, with native principal authorization and owner-bound tokens. Manufacturing events, subscriptions, multiple-sponsor journeys, resource refresh, provider mail and paid model execution are not declared. Base 0.2.86 still checks record-change events for this subset; the complete shared proof remains partial until Base supports that declaration. Do not interpret a tool's presence as delivery of the wider target manufacturing week in CONTRACT.md.

A Business owner subject binds to the native setup owner's id. Business teammate ids bind through signed settings to OA operator ids, never token email. A managed admin's initial manufacturing role is manager; a managed member's is viewer. Existing site and cost restrictions remain. Business owner is a policy owner, signed team admin is a policy editor, and member has no policy role. A local role promotion does not grant a Business policy role. Native status and configured comma-separated `AUTH_ALLOW_LIST` admission apply on every request. Empty configured admission permits nobody.

No agent token creates a native browser session. Every domain write calls the same command service as the UI; its D1 batch checks native identity, role/scope revisions, original admission revision, current policy, agent revocation, consent and Pause. Signed policy uses the installation's existing owner-claim ring. Failed Business credentials cannot become local integration credentials. Native integration keys remain restricted to their existing read API.

The registry prepares purchase orders and supplier-quote drafts, draft amendments, work and shortage drafts, exact-version proposals, subcontract drafts, kit revisions, certificate drafts, replenishment/inventory/MPS previews, isolated finite scenarios, bounded grant proposals and nesting reviews/cancellations. Read tools expose the current manufacturing snapshot, records, dated materials, pegging and supply-change suggestions. An internal draft is standard; a payroll-rate read is sensitive. Caller flags and imported text cannot choose those classes.

These preparation calls do not send supplier messages, move money, grant standing authority, adopt schedules, approve engineering/quality, release production or certify physical receipt, inspection, shipment or destruction. Existing native signature and physical-evidence doors retain those jobs. Preparing a fresh bounded grant never activates it. Revising a standing grant is outside this preparation tool because it can change existing authority. Imported documents and resource text are untrusted data. Credential fields are withheld; original file bytes remain on their native download doors. Large records retain their structure.

Resources cover items, parties, orders, purchases, jobs and operations (`job-id:sequence`), lots, inspections, cases, valuations and source history, plus prepared proposals, subcontracts, kits, certificates, planning reviews, grants, nesting groups and native labor rates. Readers reuse current native screen projections. Missing and restricted records have the same unavailable result. Reads receive company-policy decisions, approvals and audit too. The built-in `larder.events.list` is retained for the current Base registry contract; this adoption claims no manufacturing event vocabulary or subscription delivery.

Mutations require `idempotency_key`. An unchanged retry returns one retained native outcome; changed arguments conflict. Native revision-bearing amendments and cancellations also expose `expected_revision`, and their native payload version is still checked inside the write. Approval pages bind the server summary and policy revision, name the person who decides, and keep the agent as preparer. Native records, proposals, command activity and audit show “agent for person.” No Undo is advertised without a registered native reversal.

Policy unset, unanswered, expired, blocked, Business Pause, local Pause and revoked consent refuse effects. All-autonomous company policy introduces no extra policy approval, while Larder's separate manufacturing signatures remain required by the native doors. Spend is declared `none`; no provider `cost` is registered and spend caps are not enforced. Anthropic and OpenRouter remain outside this registry, so no paid-provider network edge is declared.

The setup manifest declares signed `/auth/owner-claim`. The disposable verifier signs its per-run claim and drives the real native owner lifecycle, then creates manufacturing fixtures through native commands. `rer verify` runs the shared harness and the seed journey. The journey covers each declared tool/class pair, both policies, injection, replay, changed arguments, stale revision, native activity, private reads and local Pause. Existing native tests remain in the normal Verify workflow.
